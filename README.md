# 货币战争实时助手

语言：**中文** · [English](README.en.md) · [日本語](README.ja.md)

Windows 10/11 本地悬浮助手。观察《崩坏：星穹铁道》货币战争画面，通过文字读取商店，通过手动纠正或本机学习图标记录持有角色与装备，在米游社公开攻略中匹配真实攻略码并提供运营建议。默认普通 A8·30，阵容不限。

## 攻略码查找与缓存范围

粘贴完整游戏分享文字或原始攻略码，点击“应用并锁定”。助手先检查本机缓存，找不到时联网逐页查找，并读取官方详情核对完整攻略码。使用“读取剪贴板”可以保留分享标题，利用羁绊筛选加快查找。找到后自动锁定，无需等待所有攻略同步；新对局或解除锁定会取消尚未结束的查找。

空缓存的“更新攻略”会读取普通模式公开推荐的热门和最新排序直到末尾并去重。完整同步后 24 小时内更新只重读热门前 3 页，最新排序读到整页已缓存时停止；超过 24 小时重新全量同步。增量更新不改变上次完整同步时间或完整性记录，买人和持有角色变化只补候选详情，不抓取列表。连续两次完整同步均未出现的旧攻略会从缓存清理，当前锁定的攻略保留。页数、缓存篇数、有攻略码篇数和完成状态现会持续显示。关闭程序或网络中断后保留已取得结果，下次更新继续同步；空缓存首次同步可能需要数分钟。

只有两套列表均读到末尾时才显示“公开推荐列表本次已读完”。这说明本次接口可见的普通模式推荐已读取，不保证涵盖所有历史、未公开、已删除或游戏中特定环境下的攻略。缓存用于离线继续使用，不代表始终完整或最新。未找到时可再试含标题的完整分享文字。官方标记失效的攻略不会锁定；旧版本仍需核对当前角色、装备和作者前提。查找状态独立显示，不会被观察提示覆盖。

## 使用

1. 打开游戏，进入货币战争。
2. 双击发行文件夹里的 **CurrencyWarAssistant.exe**，选择游戏窗口，点击 **开始观察**。
3. 如果你已经从攻略广场复制攻略码，把它粘贴到顶部 **本局攻略码** 输入框，点击 **应用并锁定**。也可以点 **读取剪贴板** 后再应用；允许换行、空格、“攻略码：”前缀及游戏的 `##代码##->使用说明` 分享文字。缓存未命中时会联网查找公开列表，完整分享标题可加速筛选。锁定后整局只按这篇攻略的阶段阵容、抓牌优先级、装备与经济建议，点击 **新对局** 才会解除。
4. 准备阶段打开商店。查看 **现在怎么做** 中的买人、装备、经济和下一步建议。
5. 在 **攻略与备选** 里查看一个主推荐与两个备选。可以复制攻略码、打开官方原文，或者锁定阵容。
6. **已识别** 会列出助手当前依据的信息。双击条目或点击 **识别纠正**，补充未显示的角色、装备、星级、团队等级和已选投资。出售、升星或合成后核对记录。
7. 布局不符时，点击 **查看画面 / 校准区域 / 学习图标**。框选位置区域并保存，或者框选一个完整头像/装备图标、选择名称，学习该图标。
8. 点击左上角 **设置**，会在标题上方展开设置栏，可集中调整始终置顶、无边框窗口、透明度（55%–100%）、语言（中文 / English / 日本語）和主题（深色 / 浅色）。窗口为横版布局。设置会在关闭助手时自动保存，下次启动继续使用。
9. 勾选 **无边框窗口** 可隐藏助手的系统标题栏。拖动助手标题或标题附近的空白处移动窗口；拖动右下角三角标记调整大小。右上角 **−** 最小化、**×** 关闭；按 **Esc** 或取消勾选恢复边框。此开关只改变助手窗口。

**攻略码使用位置：** 游戏内“货币战争 → 攻略大全 → 输入攻略码”。助手的复制按钮复制的是官方原始代码。

窗口可通过标题栏移动、右下角调整大小，顶部按钮折叠。真正的独占全屏可能盖住普通置顶窗口；此时在游戏设置中手动使用窗口或无边框显示。捕获黑屏、游戏关闭或最小化时，助手停止生成新画面建议。恢复后自动继续，游戏重启需重新“找窗口”。助手无边框开关与游戏显示模式是两个独立设置。

## 识别与建议的依据

- 公开版不含图标模板。商店卡片标题可通过 OCR 读取；备战、前台、后台角色与库存装备需用“识别纠正”手动补充，或在本机“学习图标”。自动识别不能替代持有与装备确认。
- 当前识别仅支持简体中文游戏客户端。英语和日语是助手界面及生成建议的语言，不能识别英文或繁体游戏文案。官方名称、效果和作者原文保留来源中文。
- 图像与中文文字识别全部在本机完成，没有付费模型或密钥。
- 联网只读取米游社公开攻略和配置；不读取游戏进程内存，不发送按键或鼠标操作，不上传截图。公开源码不内置角色、装备图标、Wiki 资料或攻略全文。
- 助手窗口默认允许 Windows 截图和录屏；游戏识别仍使用指定游戏窗口的独立捕获，不会把助手窗口当成游戏画面识别。
- 首次运行需要点击“更新攻略”获取当前公开配置和攻略；网络不可用时使用本机此前生成的缓存，界面显示更新时间。源码仓库不分发预置缓存。
- 排除官方标记失效的攻略。旧版本攻略仍需核对当前角色与装备，正文里的特定练度、星魂、环境和旧倍率不等于已满足。
- 适配分数不是通关概率。前提不足时明确提示，不把“商店出现核心”当作“已持有核心”。角色名字“花火”和“火花”及不同玩法形态分别处理。
- 必需策略/环境只在已确认选择后满足；前提提取采用明确句式，作者隐含条件仍需查看原文。
- 小图标、亮光或遮住的星级会漏读。未显示的装备与投资不能自动确认。投资页面里的选项默认“待选”，只有手动确认后才作为“已选”。
- 可见前台、后台、备战区和库存以最新识别为准；漏读的角色需手动补充。隐藏角色暂时沿用最近观察；自动记录超过3分钟没有重新看到会移除，手动补充保留至本局结束。开始下一局请点“新对局”。
- 手动移除的误识别会在本局被抑制；再次添加同名角色/装备或开启新对局后恢复识别。已装备物品可以手动指定给哪个角色。
- 手动商店是临时记录；手动刷新后点击“清除手动商店”，恢复自动读取。
- 单局持有角色和装备不在重启后恢复，避免把上局库存用到新局；区域校准和学习图标会保存。

## 文件与诊断

投资环境与投资策略三选一页面也会在“现在怎么做”中显示比较：主推荐、另外两项的当前效果、适配依据和触发条件。未锁定攻略且阵容未确认时，只按通用资源规则比较；锁定攻略后优先参考作者的环境、优选与次选策略。识别不全时显示临时建议，请在“已识别”中补充待选项。刷新或退出页面会清除待选记录；选择后需将实际选择的项目手动确认成“已选”。

保持 `.exe` 和 `_internal` 在同一文件夹，不要只复制单独的 `.exe`。直接打开程序，不需要打开终端。程序首次加载本地模型可能需要数秒。

v1.0.2 显式打包了窗口捕获组件，并增加发布版实际捕获检查。如果旧版出现 `No module named 'windows_capture.windows_capture'`，关闭旧助手，完整解压新版到新文件夹后启动；不要只替换 `.exe`。需要保留原设置与缓存时，将旧文件夹的 `CurrencyWarAssistantData` 移到新版文件夹。切换助手或游戏的无边框模式不能修复缺失组件。

`CurrencyWarAssistantData` 文件夹保存校准、图标学习、公开攻略缓存和日志。“导出诊断”保存识别结果，不会自动分享；正常运行不保存连续截图。该目录已加入 `.gitignore`，请不要上传。

## 开发与复现

Python 3.12，Tkinter，Windows Graphics Capture，RapidOCR/ONNX Runtime，OpenCV，PyInstaller。

```powershell
python -m venv .venv
.venv\Scripts\python.exe tools\prepare_capture_wheel.py --install
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe main.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m PyInstaller --noconfirm assistant.spec
.venv\Scripts\python.exe tools\verify_release.py
```

发布检查会运行打包后的 `.exe`，验证捕获组件加载、助手边框切换和对自建测试窗口的真实图像捕获；不操作游戏，也不保存游戏画面。版本变化见 [CHANGELOG.md](CHANGELOG.md)。

发行源代码包不包含游戏图像、攻略缓存、Wiki 资料或研究抓取结果。首次运行后由用户自行更新公开配置和攻略；`tools/diagnose_capture.py` 是自有捕获链路的只读校验工具。用于生成本地素材的准备脚本不进入公开源码包。

模型由 RapidOCR 包提供并随程序打包；依赖精确版本在 requirements.txt，完整开发环境版本在 requirements-lock.txt。

## 本机验证范围

历史实机检查使用过本机学习或私有模板，不能作为无模板公开版自动识别头像、星级或库存的保证。公开版可读取商店文字；持有角色、星级与库存装备需要手动补充或本机学习图标。窗口捕获、重复记录与规则逻辑分别由发布检查和合成数据回归测试覆盖。缩放识别和稳定画面检查、失效攻略、开局流萤前提、普通模式筛选、离线缓存、游戏关闭/最小化/过期截图用自动检查覆盖。

分析耗时显示在窗口中。准备画面预热后本机约2–3秒，首次加载更久；以商店变化五秒内更新为目标，低性能机器或切换动画可能超时。不同分辨率可校准，独占全屏的覆盖行为和完整游戏重启流程尚未逐项实机验证。

当前默认布局针对1920×1080。用960×540缩放图像测试时，商店与金币仍可读，头像、团队等级和部分装备有漏读，需要手动纠正或学习图标；不保证所有分辨率自动识别。

开发环境统一使用 opencv-python-headless。windows-capture 上游依赖 GUI 版 OpenCV，而 RapidOCR 依赖 headless；先运行 tools/prepare_capture_wheel.py --install，从官方 2.0.1 wheel 生成 2.0.1+cwa.headless1。本地 wheel 仅改依赖声明与分发版本，捕获源码和原生组件字节不变，并保留原许可与补丁说明。requirements-lock.txt 中的本地版本需先由该脚本生成，不能直接从 PyPI 安装。

运行依赖在 requirements.txt；打包开发依赖在 requirements-dev.txt。发布包不携带 .gitignore。许可清单检查文件目录和冻结模块两者，仅移除未包含的 pip/setuptools 许可；当前冻结模块包含 setuptools，需保留其许可。PyInstaller 许可始终保留。
